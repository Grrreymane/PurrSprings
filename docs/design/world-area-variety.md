# 世界 · 区域 · 多样性：猫猫温泉旅馆 v2 设计提案

> 视角：World, Area & Variety。管的是：更大的地图（40×36）、每颗星开一块新地方、房间差异化（房名 / 等级 / 客人类型）、无尽模式的地点和装扮（在哪买、怎么展示）、昼夜（B 期加季节）、暂停菜单、BGM 和环境音、美术清单、存档迁移、机器人指标。
> 玩家看到的字用中文，其余用英文。**价格只是用来说明节奏的占位值**，最终数字由经济视角定（`docs/design/economy_model/`，对应关系见第 17 节）。地图已经用脚本检查过（A 期全部物件、特等内汤、庭园景物都摆上时）：每行等长，812 个能走的格子全部能从柜台走到，没有死角（B 期物件也摆上时是 758 个，同样全部可达）；下面的路程表都是 BFS 实测。
> 修订记录：续写版修了初稿的 4 处问题——庭园路灯原来压在小路上（会把萤见亭整段路截断）、松树在东北角围出 2 格死角、神社本殿两边各有 1 格死角（第 1 行改成灌木）、★5 在 A 期没有新地方（现在 ★5 的大门就是星见汤，金招牌自动挂上，跟经济视角一致）；另外补了第 7.1 节区域台词、第 14.1 节「买到了什么」、A 期怎么画 B 期的地块。

## 0. 一页总结

- **地图 15×34 → 40×36**（640×576 像素，仍然是一张预渲染画布）。旧地图原样放在 col 10–24，只改了 15 个格子（4 扇新门、3 格地面、门前两侧 8 格竹篱拆掉）；**旧坐标一律 x+10**。
- **每颗星开一块看得见的新地方**，买下那块地方的大门就升星。从第一天起，这些地方就以暗色剪影出现，门口立着「★N」木牌：
  - ★2 温泉（v1 已有）
  - ★3 **食堂 + 西馆**（西翼，新动作：端早饭）
  - ★4 **庭园·别院**（东翼，4 栋小屋，新动作：搬行李）
  - ★5 **露天·星见汤**（东北角，「五星 = 看星星的汤」）；金招牌在 ★5 时**自动**挂上。木平台上的乒乓（可选的新动作）、按摩椅是 ★5 之后头几样能买的东西
  - 无尽模式（B 期）：★5 后第一个早上 **杂货铺** 开张（西南），再加 **猫神社**（西北）、**祭典广场**（东南）、四季、稀有客人。
- **房间 8 → 15 间**：本馆 8 + 西馆 3 + 别院 4。每间都有名字和暖帘纹样；三个等级「普通 / 上房 / 特等」，外观和价格都不一样；6 种客人，长相不同，对房间各有偏好。
- **昼夜**：一天 6 分钟。实现方式是正片叠底调色 + 灯笼叠加光晕，每帧约 0.3 毫秒。**季节**（B 期）每季 18 分钟。
- **暂停菜单**：右上角「⏸ 菜单」，分页 继续 / 声音 / 图鉴 / 旅馆 / 装扮（装扮在 B 期加）。
- **BGM**：5 个区域各一首曲子，每首有白天和夜晚两种编配。曲式 AABA 或 ABAB（每首 32 小节，77–101 秒），旋律由几个动机做确定性变奏生成，4 遍才完全重复一次；声部随星级增加；换区时在小节线上交叉淡入淡出；每个区域有自己的环境音。
- **分两期上线**：
  - A 期（v2.0，约 +3.9k 行）：地图 + 3 个新区域 + 房间 / 客人 + 昼夜 + 菜单 + 音乐。
  - B 期（v2.1，核心约 +2.1k 行，另有约 0.5k 行可选）：无尽模式的地方 + 商品目录 + 四季 + 稀有客人 + 宠物。
  - 两期合计约 6.0k 行，在预算 4–6k 的上沿。

## 1. 怎么守 WORKFLOW 第 3 节

| 准则 | 本设计的做法 |
|---|---|
| 不晃屏、闪烁 ≤5 次/秒 | 新区域开放时镜头是**平滑滑过去**（第 2.8 节），没有任何震动。萤火虫、星光、烟火都是渐亮渐暗，同屏每秒新增的亮点 ≤2 个，没有全屏闪白。 |
| 少字 | 新区域：图标 + 不超过 4 个字（「食堂开张」）。新动作：小手 + 不超过 3 个字（「拿托盘」）。锁着的地方：只有「★N」木牌。房名用暖帘纹样表示。 |
| 操作反馈清楚 | 每个新区域都有进度圈、头顶 / 手上的东西、气泡。升级房间时房里飘出一个字（「上」/「特」）。买下的东西 1 秒内在画面里一件件弹出来（第 14.1 节）；只有区域大门才加横幅 + 镜头巡礼。 |
| 难度低、不卡死 | 新增的每一步客人流程都有放弃计时器（放弃不生气、只是不付钱）。每个价格圈都走得到。箭头不会指进没解锁的区域。 |
| 目标真能推进 | 图鉴的剪影旁边用图标写出现条件，而且只列**当前版本做得到的**条件。 |
| 功能按钮 = 图标 + 两个字 | 「⏸ 菜单」、「▶ 继续」、「📷 拍照」…… |
| 不清存档 | v1 存档能迁移，星级**只升不降**（第 13 节）。 |
| 保留 v1 的长处 | 站进区域就干活、地上的价格圈、指引箭头，全部沿用。新动作也都是「站过去」：站在出菜台拿托盘、站到客人旁边上菜、站在行李架拿行李、站到乒乓台边打球。 |

### 6.3 分房规则（在入住进度满的那一刻决定）

### 10.2 光照怎么画（快）

在 `drawScene()` 画完按 y 排序的那一层之后、`drawOverlays()` 之前插入：

```js
const L = dayLight(S.clock);                  // { col: mix('#ffffff', tint, a), night }
if (L.a > .01) {
  g.globalCompositeOperation = 'multiply'; g.fillStyle = L.col; g.fillRect(0, 0, W, H);
  if (L.night > .05) {
    g.globalCompositeOperation = 'lighter';
    for (const lt of LIGHTS) if (VIS(lt.x, lt.y, lt.r)) { g.globalAlpha = L.night * lt.a; g.drawImage(glowArt(lt.r, lt.col), R(lt.x - lt.r) - CX, R(lt.y - lt.r) - CY); }
    g.globalAlpha = 1;
  }
  g.globalCompositeOperation = 'source-over';
}
```

- **光晕图** `glowArt(r, col)`：用代码生成，4 圈用 4×4 Bayer 抖动做透明度台阶（.5 / .3 / .18 / .08），保持像素感。按半径缓存，只有 3 种：10 / 18 / 28。
- **灯的列表** `LIGHTS`：跟着 `rebuildWorld()` 一起重建。

  | 灯 | 位置 | 半径 |
  |---|---|---|
  | 大堂吊灯 | (14,23)、(20,23) | 28 |
  | 本馆走廊灯笼 | (17,9)、(17,13)、(17,17)、(17,21) | 18 |
  | 每间开着的房的行灯 | 行灯格 | 空房 10，有人睡 18（**晚上一看就知道哪间有人**） |
  | 温泉石灯 | (12,1)、(22,1) | 18 |
  | 石灯笼 | (13,31)、(21,32) | 18 |
  | 正门暖帘 | (17,29) | 28 |
  | 食堂吊灯 | (4,24)、(7,24) | 18 |
  | 灶火 | (3,19) | 10，橙色 |
  | 庭园路灯 | (33,18)、(26,27)、(33,24)、墙灯 (26,10)、雪见灯笼 (31,17) | 18 |
  | 星见汤平台灯 | (25,7)、(38,7) | 18 |
  | 掌柜手里的小提灯 | 跟着掌柜 | 24（night > .5 时，手上画一个 3×4 的小提灯） |

- **开销**：同屏最多约 16 盏灯，加一次全屏 `multiply`。在 180×320 的画布上每帧约 0.3 毫秒。`multiply` 不支持时退回普通透明叠色。

### 10.3 夜里看得清的规则

- 价格圈的虚线框和标签、鱼干堆上的闪光、气泡、进度圈、箭头、HUD、头顶的毛巾 / 行李、手上的托盘，都在**光照之后**画，所以永远是全亮。地面层先画一遍、光照后再补画虚线框，开销很小。
- 夜里最暗的程度：叠色 α ≤ .48。掌柜自己带着提灯，永远看得清。

## 12. BGM 与环境音（全部用 WebAudio 合成）

### 12.1 引擎

- 一个**曲子播放器** `Player { song, bus, next, bar, step, sec, pass, night }`，每个挂在自己的 `GainNode` 上，再接到 `MB`（音乐总线，0.05）。交叉淡入淡出时最多同时 2 个。
- 预排时间沿用 v1 的 `musicTick` 做法：提前 0.3 秒排音符。每秒新开的声部 ≤24 个，保护手机 CPU。
- **选曲**：`wantedSong()` 按 `AREAS[玩家所在区域].music`。进菜单、★5 庆祝、夏祭这些情况有覆盖。
- **防抖**：新区域要连续待满 1.5 秒才换曲（在门口来回走不会一直切）。
- **换曲**：在旧曲**下一个小节线**上，新曲从 0 开始、增益 1.5 秒内升到目标；旧曲用 `setTargetAtTime(0, t, .6)` 淡掉，2.5 秒后停掉它的调度。
- **白天 / 夜晚**：不换曲子，只在**下一个段落**（8 小节）开始时换编配（第 12.4 节）。
- **共用回声**：一个 `DelayNode`（0.28 秒，反馈 .25，低通 2500 Hz），只给 onsen / garden 两首用，湿声 .25。
- **解锁琶音时**让音乐让路：音乐总线压到 60%，1.2 秒后恢复。

### 12.2 音色配方

| 名称 | 配方 |
|---|---|
| koto（v1 的 `pluck`） | triangle，频率 f×1.006 → f 用 50 毫秒；加一个 sine 2f 泛音；起音 6 毫秒；衰减 1.5 秒 |
| shamisen | square → 低通 2200 Hz（Q 2）；频率 f×1.02 → f 用 30 毫秒；加一个 25 毫秒的「拨子」噪声（带通 3000 Hz）；衰减 0.5 秒 |
| fue / shakuhachi | sine，150 毫秒后加 5.2 Hz、深 0.6% 的颤音；起音 60 毫秒；前 120 毫秒混一点「气声」噪声（带通 2f，Q 6，0.15）。尺八：起音从低半音滑上来，90 毫秒；释音 200 毫秒 |
| pad | 两个 triangle，±6 音分 → 低通 1400 Hz；起音 .5 秒、释音 1 秒；和弦取 3 个音放在 3–4 八度 |
| bass（v1 的 `bassNote`） | sine。lobby / onsen / garden 每小节第 1 拍一个根音；dining / festival 第 1 拍根音、第 3 拍五度 |
| musicbox | sine f + sine 3f ×.25（偏 2 音分）+ sine 5f ×.08；起音 2 毫秒；指数衰减 1.2 秒 |
| glock 闪光 | sine 2f + sine 5.4f ×.3；衰减 .6 秒 |
| woodblock | 噪声带通 1800 Hz（Q 8）35 毫秒 + sine 900 Hz 40 毫秒 |
| 小鼓「砰」 | sine 260 → 150 Hz 120 毫秒，衰减 250 毫秒 + 噪声带通 1000 Hz 20 毫秒 |
| 太鼓 | sine 90 → 48 Hz 300 毫秒 + 低通噪声 200 Hz 120 毫秒；鼓边「咔」= 高通噪声 3000 Hz 20 毫秒 |
| 手镲 | 高通噪声 5000 Hz 120 毫秒，40 毫秒后再来一下 |

### 12.4 声部随星级增加；夜晚编配；变奏

**各声部相对音量**：主旋律 .8、低音 .45、pad .18、副旋律 .5、打击 .25、闪光 .2。

| 星 | 声部 |
|---|---|
| ★1 | 主旋律 + 低音 |
| ★2 | + pad |
| ★3 | + 副旋律：B 段由副旋律唱，A3 段跟主旋律一问一答 |
| ★4 | + 打击（woodblock 打 2、4 拍；每隔一小节第 1 拍一下小鼓「砰」） |
| ★5 | + 闪光：每段最后一小节，用钟琴把和弦音琶音一遍 |
| B 期，按季节 | 春：每 16 小节笛子吹一声黄莺叫；夏：小节开头 25% 概率响一下风铃，速度 +4；秋：副旋律换成尺八，主旋律降八度；冬：白天主旋律也用八音盒，加铃铛 |

**夜晚编配**（任何一首都适用）：
- 速度 ×0.88
- 主旋律换成八音盒
- 去掉打击
- pad 降八度、音量 ×0.7
- 旋律只保留每小节第 1、3 拍上的音和句尾的音
- 每 4 小节加一个持续的高五度 + 八度长音（「星星」）

**确定性变奏**（同一首每过一遍都不一样，4 遍一循环）。变奏按 `(pass, 段落, 乐句)` 选，规则写死，不用随机数：

| 变奏 | 规则 | 用在 |
|---|---|---|
| V0 | 原样 | 每首第 1 遍的 A |
| V1 加花 | 每两个八分长的音，拆成「本音 + 上方邻音」两个八分 | A2 的第 1、2 句 |
| V2 移位 | 整句上移一个音级（终止句不动） | A3 的第 3 句 |
| V3 回声 | 句尾两个音，由副旋律高八度再唱一遍 | A3、B2 |
| V4 稀疏 | 去掉弱拍上的音 | 每首第 3 遍的 B |
| 换主奏 | 主旋律和副旋律互换 | 偶数遍 |

一遍 lobby 是 101 秒（onsen 80 秒，dining 77 秒，garden 101 秒）。4 遍一循环，再加上白天 / 夜晚两种编配和换区换曲，**同一段完全一样的音乐要隔 6 分钟以上才会再出现**（v1 是 27 秒一循环）。

```js
function migrate(raw) {   // 在 loadState 里、补默认值之前调用

  const u = raw.unlocked = raw.unlocked || {};
  const old = 1 + !!u.onsen + !!u.room6 + !!u.room8 + !!u.sign;     // v1 的星级
  if (old >= 3) u.dining = true;     // 星级不降：直接送区域大门（门里的东西照常要买）
  if (old >= 4) u.garden = true;     // 送庭园 + 花见亭
  if (old >= 5) u.roten = true;      // v1 买过招牌 = v1 五星：送星见汤（v2 的 ★5 大门）；u.sign 留着不删，招牌照样是金的
  raw.starMax = Math.max(raw.starMax | 0, old);
  raw.gift = old >= 3;               // 进游戏时一次横幅「旅馆扩建了！」+ 新区域图标，再巡礼一下
  // 声音设置不在 S 里：启动时单独做一次 if (load('music', null) === null) { const m = !!load('mute', false); save('music', !m); save('sfx', !m); }
  raw.v = 2; return raw;
}
```

- **新字段的默认值**：
  - `tier: {}`（没写就是 1；别院在 `c*` 解锁时设成 2）
  - `theme: {} / owned: {} / equip: {}` / `dex: {}`
  - `clock: .12, day: 1, dayEarn: 0` / `shrine: 0`
  - `tut: {tray, serve, luggage, pingpong}`
  - `stats.bestDay: 0`
  - 独立的键 `music / sfx`：默认 `true`（第 11.2 节）
- **鱼干堆**：沿用 v1 的过滤规则，`PILE_AT` 加上 `dining, w1–w3, c1–c4, roten, market, plaza`。
- **房间**：`S.rooms` 迭代新的 15 间 `ROOMS`。
- 坐标不存档，所以 x+10 不需要迁移。所有 v1 的 id（`room1–8, onsen, recep, maid1/2, porter, basket1/2, shoes1–3, milk, bigbath, sign`）全部保留。
- **防御**：`star()` 返回 `max(starOf(S), S.starMax)`。`star() >= 5` 但 `done` 是 false 的档（v1 刚买完招牌、还没看到庆祝就关了游戏），照 v1 弹庆祝。
- **金招牌**：`signArt(star() >= 5)`，不再看 `unlocked.sign`。

## 16. 机器人要测什么

`tests/bot.js` 和 `tests/bot_balance.js` 扩展下面这些。勤快 / 普通 / 新手三档，每档 12 个种子。

1. **节奏**：每个解锁的时间、★2–★5 的时间（对照第 4 节目标）；**两次购买之间的最长间隔**（前 5 分钟 ≤45 秒，之后 ≤60 秒 / 普通玩家 ≤120 秒）；每 5 分钟一次的「新鲜事件」都发生了（新区域 / 新动作 / 新客人类型 / 第一次天黑）。
2. **新区域真的有人去**：玩家在每个区域停留的时间占比（开放后 5 分钟内，食堂 ≥10%、庭园 ≥8%）；每分钟走路距离和 p90；走路时间 / 站在区域里干活的时间。
3. **新动作的瓶颈**：等饭放弃了几次、行李超时几次、毛巾放弃几次、乒乓等不到对手几次（按星级分）；雇员工前后对比（雇了配膳员以后，等饭放弃应该降到 <5%）。
4. **客人和房间**：每类客人入住时偏好满足的比例（挑剔客人满足率 ≥60%）；每个等级的房间收入占比；入住率按区域分；生气离开 < 3%（雇前台以后）；因为上限卡住、没能出客的时间占比 < 10%。
5. **经济**：每星每分钟收入；★5 时手上的钱。无尽模式（B）：便宜的商品 ★5 后 ≤5 分钟买得起；4 小时内买下 50% 的目录；神社 10 级的时间。
6. **昼夜**：白天、夜里每分钟收入差 ≤10%（夜里不惩罚玩家）；每帧灯的数量（≤16）；`render()` 扫一遍「每个区域 × 4 个时段 ×（B）4 季」不报错，出一张截图总表人工看。
7. **指引**：100% 的箭头目标 `findPath ≠ null`、不在锁定区域里；机器人认得每一种 `GUIDE.kind`（遇到不认识的就报错，不要静默卡住）。A 期构建里不存在指向 market / shrine / plaza 的 ★ 牌或价格圈。
7b. **地图**（`tests/map_check.js`，不用跑游戏）：每个解锁组合（按解锁表顺序一步步买）下，能走的格子全部从柜台可达；所有价格圈、座位、泡汤位、站位、观景点、鱼干堆都在能走的格子上（价格圈允许压在买下后才出现的物件上）；第 2.6 节的格数不变。
7c. **买到了什么**：每次购买后 1 秒内，要么新东西的格子在镜头里，要么屏幕边有指向它的带图标箭头（第 14.1 节）。
8. **不变量**（每秒查一次）：v1 那些照旧 + 每个座位 / 泡汤位 / 乒乓站位最多 1 人 + 手上的托盘 ≤ 上限 + 每个箱子只在一个地方（架上 / 头上 / 送到了）+ 没有实体站在 `BLOCK` 格上 + 没有客人在锁定区域里 + 星级 ≥ `S.starMax`。
9. **音乐**（headless 读调度器的状态）：正常走路时每分钟换曲 ≤4 次（防抖有效）；每秒新开的声部 ≤24；同一首里同一段（同样的段落 + 变奏 + 编配）两次出现至少隔 6 分钟。
10. **存档**：v1 的 ★1–★5 存档（还有几种怪形状）读进来 → 继续玩 10 分钟不报错，星级不降、钱不变；v2 存档随时存 → 读 → 往返一致。
11. **性能**（`tests/perf_render.js`）：最挤的画面（夜里、庭园、48 个实体、B 期加粒子）每帧 `update + render` < 4 毫秒（headless 估算）。

### 17.2 风险和注意事项

- **单文件行数**：A 期之后约 6,800 行，B 期之后约 8,900 行（加上可选部分约 9,400 行），会碰到 `CLAUDE.md` 的换引擎信号「单文件超过约 8000 行」。建议在 A、B 之间**问用户**要不要拆 `src/` 模块 + 构建脚本（参考一喵天下 / 光速逃亡）。不擅自拆。
- **「大地图滚动」信号**：不适用。地图只有 640×576，静态层预渲染一次，canvas 绰绰有余，不需要 Phaser。
- **并行开发**：几个代理同时改时，照 WORKFLOW 第 5 节：主文件先在 scratchpad 里改；美术分 env / objects / chars 三段并行；合并后统一跑 `subset_font.py`（新字很多：房名、横幅、商品名）。
- **最大的玩法风险**：新动作太多，变成到处救火。对策：
  - 每个新动作在它那颗星的前 1–2 分钟就能雇员工接手（配膳 250、行李 900，都是那一段里最先出现的圈之一）；
  - 箭头一次只指一件事；
  - 乒乓永远是可选的。
